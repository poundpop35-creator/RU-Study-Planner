# การเปิดใช้สมุดร่วมกัน (RU Study Planner)

**ใช้เฉพาะ Supabase โปรเจ็กต์ yikfrloyijdbwglswcww** ซึ่งกำหนดใน dist/supabase-config.js
โปรเจ็กต์ที่ต่ออยู่ในเครื่องมืองานนี้คือ pysxrpsdpttddhraewcm (คนละฐานข้อมูล) จึงห้ามติดตั้ง SQL ไปที่นั่น

## ขั้นตอนก่อนเปิดใช้จริง

1. สำรองสมุดเดิม และยืนยันว่ากำลังทำงานกับ repo poundpop35-creator/RU-Study-Planner
2. ใน Supabase Dashboard ของโปรเจ็กต์ yikfrloyijdbwglswcww ตรวจตารางและ policy ปัจจุบันก่อน แล้วให้เจ้าของโปรเจ็กต์รันไฟล์ database/ru_collab_notes.sql ผ่าน SQL Editor
3. เปิด Supabase Auth แบบ Email พร้อมยืนยันอีเมล ตั้ง Site URL และ Redirect URL ให้ถูกกับโดเมน study-plan-phi-six.vercel.app
4. ใน Realtime Settings ปิด Allow public access เพื่อ enforce private channels; ตรวจว่าไม่มี policy เดิมใน realtime.messages ที่อนุญาตกว้างเกินไป
5. ตรวจ policy ใน storage.objects ว่า bucket ru-collab-assets เป็น private และบัญชีที่ไม่ใช่สมาชิกดาวน์โหลดไม่ได้
6. ใช้ 2-3 บัญชีจริงในการทดสอบสิทธิ์พร้อมกันก่อน Merge ขึ้น production

## วิธีใช้

- เปิดหน้า สมุดจด → สมุดร่วมกัน (เส้นทาง #collab)
- เข้าสู่ระบบ Supabase Auth แยกจากลิงก์สมุดเดิม
- สร้างสมุดร่วมกันใหม่ หรือกด แชร์เพื่อทำงานร่วมกัน จากหน้าโน้ตส่วนตัวเดิม ระบบจะทำสำเนาของหน้าโน้ตนั้นและคัดลอกรูป/เอกสารไปยังพื้นที่ร่วมกัน โดยไม่แตะต้นฉบับ
- เจ้าของเชิญด้วยอีเมลที่มีบัญชีและยืนยันแล้ว เลือกสิทธิ์ editor หรือ viewer
- ผู้รับเปิดลิงก์ #collab-note/<note-id> ด้วยบัญชีตนเอง
- หน้าโน้ตแสดงสถานะบันทึก ผู้ใช้ออนไลน์ รายการสมาชิก การเปลี่ยนสิทธิ์/ถอนสิทธิ์ และประวัติฉบับก่อน

## ขอบเขตการทำงานร่วมกัน

การแก้ไขคนละวัตถุพร้อมกันใช้ optimistic compare-and-swap กับการ merge แบบสามทางระดับวัตถุ และส่งเลข revision ผ่าน Realtime Broadcast (ไม่ส่งเนื้อหาสมุดใน Broadcast)
ถ้าแก้ **กล่องข้อความหรือวัตถุเดียวกันพร้อมกัน** จะไม่เขียนทับอย่างเงียบ ๆ แต่แจ้งข้อมูลชนกันและเก็บสำเนาร่างให้สำรอง นี่จึง **ยังไม่ใช่ CRDT รายตัวอักษรแบบ Canva/Yjs เต็มรูปแบบ**
หาก Realtime ใช้ไม่ได้ จะตรวจการเปลี่ยนแปลงทุก 5 วินาทีเป็นทางสำรอง

- [ ] A/B แก้ข้อความเดียวกันพร้อมกัน: มีการแจ้ง conflict และสำรองได้

## ข้อจำกัด

ระบบร่วมกันใช้ **Supabase Auth** และสิทธิ์รายบัญชี ไม่ใช่การเปิดลิงก์ให้ใครก็ได้แก้โดยไม่สมัครบัญชี อย่าปรับเป็น public storage/public realtime เพียงเพื่อข้ามขั้นตอนเข้าสู่ระบบ เพราะจะทำให้เนื้อหาสมุดรั่วไหลได้
